# Vinci challenge

This repository serves to store the coding challenge for Vinci client.

## Option B - Tetris

### Goal

The goal of this challenge is to build the classic Tetris game. You can find all the requirements under <a href="./CHALLENGE.md#option-b-tetris">CHALLENGE Option B</a>

### Decisions

**Use plain React with Vite**/
Since we are building a tetris game, we don't need any server features (or at least nothing too complex). For that reason, setting up the project with Vite is good enough for now.
We can migrate to any framework if needed later, but there is no need to add extra complexity for now.

**Rotation mechanics**/
I implemented a basic logic of rotation. Initially I thought about rotating the pieces on demand, but since we have a limited number of pieces and rotations, we can easily store all the rotations in memory and rotate them as needed, saving time and computing power.

**Components Directory**/
I choosed a feature based approach to organize the components for simplicity. Even though I'm a fan of Atomic Design approach, I felt that it was not necessary for this challenge since the components we were building were not being reused across the app (at least for now).

**Scene Elements**/
To ensure we only use the scene to render the minimun as possible, I use global state to track things like next piece, score and level to be able to render them outside of the scene.


### Trade-offs
- To avoid overcomplicating the styling, I used inline styles and some css classes. Ideally we would have something like Tailwind installed.


### How to run

To run the game locally, first clone the repository:
```bash
$ git clone https://github.com/ekumenlabs/vinci_lucas_ferreyra.git
```

Then navigate to the project directory:
```bash
$ cd vinci_challenge
```

Install dependencies:
```bash
$ npm install
```

Run the development server:
```bash
$ npm run dev
```

### Next Steps

**Rotation logic**/
Is not the same as classic tetris. Right now, you cannot rotate on the borders of the screen. There is also a known issue where if you rotate while moving the piece, it looks snappy.


### AI Usage

1. While working on calculating the different pieces and the rotation possibilities, Gemini generated methods to rotate the pieces matrix and get bounds for a specific rotation. My approach would have been to manually write down the possible rotations for each piece since there are only 7 pieces and 4 rotations.

2. The initial bootstrap to render the scene and show something is the screen, was generated by Gemini. Even though it helped to get started, the approach was not ideal. For instance, it relies mainly on useState and the initial approach was setting the state within the render loop which it is known to be a bad practice.
This initial setup condemn me to use a mix between the hook that provides state, the state for pieces and some refs. Also it makes it harder to include a global state for the game state without needing a big refactor.
